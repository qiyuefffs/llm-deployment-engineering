# R34 · 多节点部署排障
### 多节点部署排障：Ray / NCCL / RCCL / vLLM

> 适用目录：`05-多卡多节点/多节点部署排障.md`

> 关键词：双节点、Ray 能连但模型加载失败、NCCL hang、RCCL 通信失败、vLLM 多节点

---

#### 1. 核心原则

多节点部署要分三层：

```text

控制面：Ray 是否能连接节点

数据面：NCCL/RCCL 是否能完成 GPU 通信

模型面：vLLM 是否能加载权重并完成推理

```

判断顺序：

```text

Ray 能连上

  只能说明控制面通了

NCCL/RCCL all-reduce 成功

  才说明 GPU 数据面通了

vLLM 成功加载模型

  才说明分布式推理链路闭环

```

---

#### 2. 标准排障顺序

不要一上来直接跑大模型。

正确流程：

```text

1. 节点基础网络检查

2. GPU/驱动/CUDA/ROCm 检查

3. 框架版本一致性检查

4. NCCL/RCCL tests

5. PyTorch distributed all-reduce

6. Ray cluster 启动

7. Ray GPU 资源检查

8. vLLM dummy load

9. 小模型真实加载

10. 目标大模型真实加载

11. 压测 TTFT / TPOT / throughput

```

#### 6. Ray 能连但模型加载失败：重点排查

##### 6.1 模型路径是否两个节点一致

如果启动：

```bash

--model /data/models/deepseek-r1

```

两个节点都必须有：

```bash

ls -lh /data/models/deepseek-r1

du -sh /data/models/deepseek-r1

find /data/models/deepseek-r1 -maxdepth 1 -type f | wc -l

```

Ray 不会自动复制模型权重。

---

##### 6.2 Ray 是否识别 GPU

```bash

ray status

ray list nodes

```

你要看到：

```text

2 nodes alive

GPU: 正确数量

```

如果 GPU 是 0，排查：

```text

驱动不可见

Ray 启动环境没有 GPU 权限

容器没有挂载 GPU 设备

CUDA_VISIBLE_DEVICES / HIP_VISIBLE_DEVICES 设置错误

```

---

##### 6.3 vLLM 是否选错 IP

多网卡机器设置：

```bash

# Node 1

export VLLM_HOST_IP=<NODE_IP>

# Node 2

export VLLM_HOST_IP=<NODE_IP>

```

如果不设置，vLLM 可能选到：

```text

127.0.0.1

docker0

virbr0

错误的管理网卡

```

---

##### 6.4 环境变量是否传给 Ray worker

建议在每个节点 `ray start` 前设置：

NVIDIA：

```bash

export VLLM_HOST_IP=<当前节点IP>

export NCCL_DEBUG=INFO

export NCCL_DEBUG_SUBSYS=INIT,NET,COLL

export NCCL_SOCKET_IFNAME=eno1

export NCCL_IB_DISABLE=1

export CUDA_VISIBLE_DEVICES=0,1,2,3

```

AMD：

```bash

export VLLM_HOST_IP=<当前节点IP>

export NCCL_DEBUG=INFO

export NCCL_DEBUG_SUBSYS=INIT,NET,COLL

export NCCL_SOCKET_IFNAME=eno1

export NCCL_IB_DISABLE=1

export HIP_VISIBLE_DEVICES=0,1

export ROCR_VISIBLE_DEVICES=0,1

```

#### 7. dummy load 判断问题归属

```bash

vllm serve /data/models/large-model \

  --distributed-executor-backend ray \

  --tensor-parallel-size 4 \

  --pipeline-parallel-size 2 \

  --load-format dummy \

  --max-model-len 2048

```

判断：

| 结果 | 说明 |

|---|---|

| dummy 成功，真实加载失败 | 权重文件、显存、safetensors、磁盘 IO、dtype |

| dummy 失败 | Ray worker、NCCL/RCCL、GPU 调度、IP、TP/PP 配置 |

#### 8. TP/PP 配置排查

双节点建议：

```text

TP = 每节点 GPU 数

PP = 节点数

```

##### 2 节点，每节点 8 卡

```bash

--tensor-parallel-size 8 \

--pipeline-parallel-size 2

```

##### 2 节点，每节点 4 卡

```bash

--tensor-parallel-size 4 \

--pipeline-parallel-size 2

```

不建议直接：

```bash

--tensor-parallel-size 16

```

原因：

```text

跨节点 TP 会让每层 all-reduce 都走网络

通信压力非常大

容易 NCCL/RCCL hang

```

#### 9. NVIDIA 双节点部署模板

##### Node 1

```bash

export VLLM_HOST_IP=<NODE_IP>

export NCCL_DEBUG=INFO

export NCCL_DEBUG_SUBSYS=INIT,NET,COLL

export NCCL_SOCKET_IFNAME=eno1

export NCCL_IB_DISABLE=1

export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7

ray stop -f

ray start --head \

  --node-ip-address=<NODE_IP> \

  --port=6379 \

  --dashboard-host=0.0.0.0

```

##### Node 2

```bash

export VLLM_HOST_IP=<NODE_IP>

export NCCL_DEBUG=INFO

export NCCL_DEBUG_SUBSYS=INIT,NET,COLL

export NCCL_SOCKET_IFNAME=eno1

export NCCL_IB_DISABLE=1

export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7

ray stop -f

ray start \

  --address='<NODE_IP>:6379' \

  --node-ip-address=<NODE_IP>

```

##### Head Node 启动 vLLM

```bash

vllm serve /data/models/large-model \

  --distributed-executor-backend ray \

  --tensor-parallel-size 8 \

  --pipeline-parallel-size 2 \

  --max-model-len 4096 \

  --gpu-memory-utilization 0.9

```

#### 10. AMD/W7900 双节点经验总结

你之前的场景：

```text

2025 年

双节点服务器

W7900

DeepSeek-R1

Ray 可以连接

RCCL 通信失败或模型无法加载

```

高概率原因：

```text

1. RCCL 选错网络接口

2. 两节点 ROCm/RCCL/PyTorch/vLLM 版本不一致

3. Ray / torch distributed master addr / rank 配错

4. 防火墙、端口、hostname、容器网络问题

5. IB/RDMA 没配好，或者误走 IB

6. W7900 作为工作站卡，多节点 RCCL 验证不如 MI 系列成熟

7. PCIe / NUMA / NIC 拓扑导致通信不稳定

8. DeepSeek-R1 TP/PP 切分不合理

9. 显存不足或模型路径不一致

```

正确复盘话术：

> 当时 Ray 可以把两个 W7900 节点拉成集群，但 vLLM 无法加载模型。这个现象说明 Ray 控制面是通的，但不能证明 GPU 执行面、模型文件访问和 RCCL 通信都正常。我会把问题拆成四类：模型路径和缓存一致性、Ray GPU 资源识别、vLLM/Ray IP 一致性、RCCL collective 初始化。

#### 11. 常见错误速查表

| 现象 | 优先排查 |

|---|---|

| Ray 能连，模型加载失败 | 模型路径、GPU 资源、VLLM_HOST_IP、NCCL/RCCL |

| Ray 只显示一个节点 | worker 没连上、端口、防火墙、head IP |

| Ray 显示 GPU=0 | GPU 权限、CUDA_VISIBLE_DEVICES、容器设备 |

| vLLM 卡在 loading model | 模型文件、显存、safetensors、worker died |

| NCCL hang | 网卡、IB/RDMA、NCCL_SOCKET_IFNAME、端口 |

| RCCL hang | 网卡、ROCm/RCCL 版本、IB、W7900 支持边界 |

| 单节点能跑，双节点失败 | 网络、NCCL/RCCL、TP 跨节点、Ray IP |

| dummy 成功真实失败 | 权重/显存/IO |

| dummy 失败 | 调度/通信/IP/并行配置 |
