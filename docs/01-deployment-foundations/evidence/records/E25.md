# E25 · vLLM ROCm 部署方案

来源文件：`deployment.md`。工程部署方案；命令覆盖 Docker 与原生路线，运行状态以独立报告为准。

本页为脱敏归档：仅替换私人路径、地址、身份、摘要值及附件引用；历史措辞与失败记录保留。命令中的尖括号为占位符，不能原样在 shell 中执行；已执行事实与部署方案按来源说明区分。

## 阶段 1：Docker 与原生部署方案

### 共同前提

本项目不安装 ROCm/CUDA 驱动、不写 GRUB、不改 BIOS。共同前提如下：

- Linux x86_64；本机为 Ubuntu 24.04.4 LTS；
- `/dev/kfd` 与 `/dev/dri` 存在；
- 用户属于 `render`、`video`，使用 Docker 时还需有 Docker 权限；
- Ryzen AI MAX+ 395 使用 ROCm 7.0.2+；本机为 ROCm 7.2.4；
- RDNA3.5 的 TTM/GTT 共享内存上限应覆盖目标模型；AMD 官方建议 firmware VRAM carve-out 保持较小并扩大共享 TTM/GTT。本机两者均约 117.19 GiB；
- Hugging Face 缓存应至少预留“最大模型权重 × 1.2”，全矩阵需要数百 GiB 磁盘；
- gated 模型需要先接受许可证并设置 `HF_TOKEN`。

### 方案 A：Docker

#### 框架

- vLLM official ROCm image：默认 `vllm/vllm-openai-rocm:nightly`；
- 正式报告应将镜像固定为 digest，例如 `image@sha256:...`；
- 宿主机只提供内核驱动和设备节点，ROCm 用户态、PyTorch、Triton 与 vLLM 来自镜像。

#### 依赖清单

| 依赖 | 要求 | 作用 |
|---|---|---|
| Host ROCm/amdgpu | 用户已安装，ROCm 7.0.2+ | 内核与 KFD；脚本不安装 |
| Docker Engine | 可访问 `/dev/kfd`、`/dev/dri` | 容器运行时 |
| vLLM ROCm image | official `vllm/vllm-openai-rocm` | PyTorch/vLLM/Triton 用户态 |
| 磁盘缓存 | 建议独立 NVMe | 模型下载与复用 |
| Python 3.10+（宿主） | benchmark harness 仅标准库 | 编排、HTTP 测试、CSV/SVG |

#### 启动

只启动服务：

```bash
MODEL_ID=Qwen/Qwen3-VL-4B-Instruct \
ATTENTION_BACKEND=TRITON_ATTN \
FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE \
docker compose -f docker/compose.yaml up
```

compose 默认服务针对 Qwen3-VL 固化 `--enforce-eager`、0.5 memory fraction 和 262144-pixel 视觉上限。切换到非 Qwen 架构时，优先使用 benchmark runner 的模型级配置；不要把 Qwen processor kwargs 机械传给 DeepSeek/Gemma。

完整 benchmark：

```bash
VLLM_IMAGE=vllm/vllm-openai-rocm:nightly \
./scripts/run_benchmark.sh \
  --runtime docker \
  --model qwen3_vl_4b_instruct \
  --attention-modes flash_on,flash_off
```

如果 Docker Hub 无法拉取官方镜像，但 `wheels.vllm.ai` 可访问，可基于本机已有的 `rocm/pytorch:latest` 构建锁定 wheel 的本地镜像：

```bash
./scripts/build_local_vllm_image.sh
VLLM_IMAGE=rocm395/vllm:0.20.2rc1-rocm721 \
  ./scripts/run_benchmark.sh --runtime docker --model qwen3_vl_4b_instruct
```

该 fallback 使用固定提交 `321fa2d6d...` 的 ROCm 7.2.1 wheel，不安装或改动宿主驱动。

容器关键参数：

- `--device=/dev/kfd --device=/dev/dri`：传入 ROCm 设备；
- `--group-add=video`：匹配设备权限；
- `--ipc=host`：避免共享内存过小；
- `--cap-add=SYS_PTRACE --security-opt seccomp=unconfined`：与 vLLM ROCm 上游示例一致；
- Hugging Face cache bind mount：避免每个 attention 组重复下载；
- 不使用 NVIDIA runtime，也不安装 CUDA。

#### Docker 环境修改项

宿主必需变更：

1. TTM/GTT 共享内存上限；本机已约 117.19 GiB，无需脚本修改；
2. 用户需要 `video`、`render`、`docker` 权限；本机已满足；
3. 创建 Hugging Face 缓存目录；脚本会创建目录但不改变系统权限策略；
4. 可选设置 `HF_TOKEN`、`HF_ENDPOINT`、`HF_CACHE`；
   使用不代理 Xet CAS 的镜像站时设置 `HF_HUB_DISABLE_XET=1`；
5. 无驱动、内核模块、ROCm apt 仓库自动变更。

如果组织网络无法使用 Hugging Face/Xet，而获准镜像支持 HTTP Range，可用附带脚本预取单个已知文件；必须同时提供上游字节数和 SHA-256，校验通过后才会落成最终文件：

```bash
./scripts/download_range_parallel.sh \
  '<approved-mirror-url>' \
  '<huggingface-cache-blob-path>' \
  '<exact-size-bytes>' \
  '<upstream-sha256>' \
  8
```

这不是通用模型转换工具，也不会绕过 gated 许可。正式报告应记录镜像来源和 checksum；不确定哈希时不要使用。

### 方案 B：原生本地环境

#### 框架

- vLLM ROCm wheel；
- Python 3.12 独立虚拟环境；
- 默认 wheel 源为 `https://wheels.vllm.ai/rocm/nightly/rocm721`；
- 本机 ROCm 7.2.4 可承载 ROCm 7.2.1 用户态 wheel，正式复现仍应锁定 vLLM commit。

#### 依赖清单

| 依赖 | 要求 | 作用 |
|---|---|---|
| Host ROCm | 7.0.2+；本机 7.2.4 | 用户维护，脚本不安装 |
| Python | **3.12** | 上游 ROCm wheel 硬要求 |
| uv | 当前用户可执行 | 创建托管 Python 3.12 venv，避免 CUDA wheel 回退 |
| vLLM ROCm wheel | nightly `rocm721` 或固定 commit | 推理服务 |
| 项目包 | editable install，无运行时第三方依赖 | benchmark harness |

#### 安装

```bash
python3 -m pip install --user uv
./scripts/setup_native.sh
source .venv/bin/activate
```

固定 vLLM 提交：

```bash
VLLM_COMMIT=<upstream-commit-sha> \
VLLM_ROCM_VARIANT=rocm721 \
./scripts/setup_native.sh
```

运行：

```bash
source .venv/bin/activate
./scripts/run_benchmark.sh \
  --runtime native \
  --model deepseek_vl2_tiny \
  --attention-modes flash_on,flash_off
```

#### 原生环境修改项

1. 在项目目录创建 `.venv`；
2. uv 可按用户级安装，不要求系统 Python 替换；
3. `.venv` 内安装 vLLM ROCm wheel、其绑定的 PyTorch/Triton 依赖和本项目；
4. 不要向当前 Python 3.13 环境直接 `pip install vllm`，否则可能选择 CUDA wheel；
5. `PYTORCH_ROCM_ARCH=gfx1151` 仅在源码编译时设置；预编译 wheel 不需要；
6. 不建议设置 `HSA_OVERRIDE_GFX_VERSION`，因为当前上游已经识别 `gfx1151`；
7. Flash 组由脚本设置 `FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE` 和 `--attention-backend TRITON_ATTN`；关闭组设置 `FALSE` 和 `ROCM_ATTN`；
8. AMD RDNA3.5 共享内存说明见 [AMD RDNA3.5 system optimization](https://rocm.docs.amd.com/en/latest/reference/system-optimization/rdna3-5.html)。
9. 当前固定 wheel 在 gfx1151 上需要 `--enforce-eager`；这是避免已实测 compile GPU hang 的用户态 workaround，不修改驱动。Qwen 还需限制视觉 profile，DeepSeek-VL2 需遵守 4096 context 上限。

### 镜像/wheel 锁定

nightly 适合适配最新模型，但不是长期复现标识。拿到第一轮成功结果后：

1. 记录 `manifest.json`、server log 中的 vLLM/PyTorch/ROCm 版本；
2. Docker 用 `docker image inspect` 记录 digest；
3. 原生用对应的 vLLM commit wheel URL 重建；
4. 不要在同一报告中混用不同 digest/commit；
5. attention backend 变化时视为新的实验环境。
