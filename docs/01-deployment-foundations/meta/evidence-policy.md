# 证据使用与数据边界

## 一、采信顺序

1. 设备实例页用于回答适用范围、执行顺序和结果如何解释。
2. `Rxx` 保存迁移前的完整技术正文。命令、失败日志和原始表格以 R 正文为准。
3. `Exx` 说明来源覆盖、测量限制和仍未补齐的字段。
4. `measurements.json` 只保存已确认可公开的结构化字段；缺失值保持缺失。

## 二、可以声明什么

- 原始记录中实际出现的版本、参数、输出和失败可以保留。
- 单次观察可以写成“本次观察”，不能写成稳定吞吐或设备保证值。
- 多变量同时变化的实验可以报告组合结果，不能把收益归因给其中一个参数。
- 建议命令可以保留为操作说明，但必须与已经执行的命令分开。

## 三、不可越过什么

- 未运行的项目不填性能数字，不把预测改写成实测。
- 不补造模型 revision、镜像 digest、逐请求文件、质量分数或资源峰值。
- 私人路径、节点、凭据、业务输入和未授权附件不进入正文。
- 原始 R 正文不因编辑需要被压缩或删除；实例页保留关键命令、检查点、结果复算和解释，完整过程仍可跳转。

脱敏是正文保留规则的明确例外：只替换私人路径、节点、登录身份、凭据和
模型摘要占位符，不改技术参数、计时、失败现象或结论。迁移前的
`reports/evidence-hashes.json` 不覆盖；需要替换的 R 记录另存脱敏前后摘要与
替换类别到 `reports/evidence-sanitization.json`，校验器同时检查基线对应和
脱敏后正文。因而“证据保留”不等于所有正文仍逐字未变。

E21–E32 为补充项目资料的脱敏快照，来源文件名、来源性质和校验值由
`reports/project-evidence.json` 登记。其中 E23/E24 是随制品的模型说明，
其作者报告不能写成本机实测；E25/E26 是部署与测量方案，其命令也不自动
表示所有组合已运行。其余本地报告仍以各自日期、版本和负载为限。

## 四、引用方式

实例页在结果段标注 `Rxx`、`Exx` 或 `measurements.json` 字段。教程页引用实例编号 `Cxx`，不复制整张结果表。来源编号只代表材料归属，不代表本轮重新运行。
