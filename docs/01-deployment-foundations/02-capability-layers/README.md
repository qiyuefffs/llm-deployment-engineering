# 第二部分：五层能力详细框架

## 本部分概览

这一部分是全书主体，沿用原框架的五层与节编号。每章先介绍这一层的职责和机制，再进入具体操作。需要较长篇幅的平台教程与实验放在子章节中，通过目录按顺序阅读。

## 五章怎样衔接

[第1章硬件后端适配](01-hardware-backends.md)从设备和软件兼容关系开始。完成后，读者应知道当前设备可以选择哪条执行路线，以及怎样验证这条路线。

[第2章模型格式与量化](02-model-formats-quantization.md)准备对应制品。完成后，应能说明文件来源、格式、精度、模板和校验结果，并理解转换与量化的区别。

[第3章推理框架](03-inference-frameworks.md)把制品变成服务。它先解释vLLM与llama.cpp的运行结构，再讲构建、启动和接口检查。OpenVINO与Apple路线作为对应平台的配套教程展开。

[第4章显存与性能优化](04-memory-performance.md)先预算，再测量，最后做实验。它将四个常见问题分别处理：内存不足、首token慢、生成慢和并发上不去。

[第5章工程交付](05-engineering-delivery.md)把最终配置、测试结果和维护方式固定下来。项目交付以七项结果收束，知识点不再停留在临时终端里。

## 实例的阅读顺序

初次学习可以先做[Windows CPU完整入门演练](../practice/first-service/README.md)，它提供可公开的真实输入和本轮输出。然后依据设备选择NVIDIA、AMD、Intel、Apple或昇腾章节。

同一节中的步骤采用连续目录与统一别名。需要切换平台时会进入新的子章节；不同平台的数值在对应实例中解释，完整来源集中放在文末资料索引。

## 操作前的准备

准备一个独立项目目录，保留模型、日志和结果的位置；确认磁盘足够，当前Python环境与终端一致。系统驱动与Runtime按目标设备的支持组合准备，已有环境先记录再修改。

本书命令用本机回环地址提供实验服务。平台教程中的资源要求与已知限制应先读完，再下载大模型或编译源码。
