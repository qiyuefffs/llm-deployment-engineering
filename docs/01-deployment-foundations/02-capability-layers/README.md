# 第二部分：五层能力详细框架

[总目录](../SUMMARY.md) · [设备工程实例](../engineering/README.md)

五层按“硬件怎样被调用 → 模型怎样表示 → 引擎怎样执行 → 性能怎样优化 → 服务怎样交付”展开。通用概念和选择方法在主框架，平台专题补充软件栈差异，实际设备记录用于验证和复用。

| 层 | 节编号 | 技术范围 | 理解目标与工程落点 |
| --- | --- | --- | --- |
| [1.硬件与运行时](01-hardware-backends.md) | 1.1—1.4 | CPU/GPU/NPU、内存与带宽、驱动/Runtime、计算库、构建与通信 | 看懂平台软件栈，选择并验证执行路线 |
| [2.模型格式与量化](02-model-formats-quantization.md) | 2.1—2.6 | HF/GGUF/IR、W/A/KV、AWQ/GPTQ、制品完整性 | 固定模型与质量基线 |
| [3.推理框架](03-inference-frameworks.md) | 3.1—3.6 | 加载、执行器、KV、调度、API、后端构建 | 可调用服务与有效参数 |
| [4.显存与性能](04-memory-performance.md) | 4.1—4.6 | 内存模型、指标、负载、缓存、推测、并行 | 基线、实验与验收 |
| [5.工程交付](05-engineering-delivery.md) | 5.1—5.3 | 环境、启停、SSE、监控、恢复、交付清单 | 完整部署包与运行记录 |

## 资料分工

- 主框架：技术定义、组件结构、执行机制、选型、参数与判断条件。
- 平台专题：先介绍硬件与运行时，再展开配置、部署与故障解释。
- [完整工程记录](../engineering/README.md)：具体GPU的执行顺序、优化过程和50份FlowUs技术原文。
- [结果与来源](../evidence/README.md)：历史环境、结构化数字、核算与缺项。

## 适配顺序

```text
设备与最小计算 → 模型完整性 → 单请求正确 → API/SSE/异常
 → 基线与峰值 → 对照优化 → 质量/性能/资源验收 → 交付/回滚
```

模型尚不能正确执行时，先处理支持与功能；进入优化后固定模型、输入和计时边界。各设备的环境与数字不跨记录合并成一套运行组合。
