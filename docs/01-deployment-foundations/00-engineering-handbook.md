# 00 怎样使用这套工程知识体系

[返回总目录](README.md) · [开始第 01 章](01-engineering-and-request.md)

正文按实际部署顺序编排。从头学习时直接读 01～13；这页只说明材料怎样使用，不另起一套知识框架。

## 1. 一次部署按四个阶段推进

| 阶段 | 章节 | 进入下一阶段的条件 |
| --- | --- | --- |
| 准备 | 01～04 | 目标清楚、环境兼容、模型完整、资源预算成立 |
| 跑通 | 05～07 | 目标模型能在目标设备运行，正常/异常接口经过检查 |
| 验证与优化 | 08～11 | 有固定负载、基线、对照、质量及资源结果 |
| 交付 | 12～13 | 有版本清单、启停、恢复、监控、验收与来源 |

构建失败时先到第 10 章查对应阶段。不要在加载和功能尚未通过时，用大量并发测试寻找答案。

## 2. 先选一条主线，再看平台差异

第一次跟做可选第 05 章的 A10 / llama.cpp 路线：获取固定 GGUF → 构建 → 启动 → 功能检查 → 第 08 章压测 → 第 09 章 FA 对照。原有完整材料在[独立 Case](../../cases/llama-cpp-flash-attention/CASE.md)。

如果目标是自己的 Intel、AMD 或 Mac，先完成第 02～04 章，再去第 06 章选择后端和模型制品。A10 的编译架构、工具链与速度不能直接套到另一台设备。

已有 vLLM 模型与服务时，可从第 07 章核对启动配置，再到第 08 章建立基线。

## 3. 每种材料怎样判断

| 正文标记 | 应当怎样使用 |
| --- | --- |
| 已有实例 / 原记录 | 对照设备、版本、输入和测试条件阅读；结果只代表那次运行 |
| 命令结构 / 模板 | 先满足写明的前提，再按现场路径和版本调整；未表示本轮运行成功 |
| 教学算例 | 用给定参数理解计算，不替代目标模型配置 |
| 待补 / 未验证 | 保留缺口，后续补实验；不当成已支持的功能 |
| 本轮离线核对 | 本机实际运行的文件、计数和算术检查，不含模型推理 |

FlowUs 历史结果以[技术转录](evidence/measurements.json)提供。它们帮助解释真实问题，缺失的逐请求文件、完整日志和模型 revision 已在对应章节说明。[证据说明](evidence/README.md)集中列出这些限制。

## 4. 执行命令前确认四件事

1. **在哪里执行：** 仓库根目录、Case 目录、模型源码目录或目标设备终端。
2. **前提是什么：** 操作系统、权限、后端、依赖、可用内存和磁盘。
3. **什么会变化：** 安装包、下载文件、启动服务或创建输出目录。
4. **怎样检查：** 退出码、版本、日志、接口、文件或指标。

代码块中的 `/srv/models/example-model` 等是占位路径。先替换为自己准备好的完整制品。Linux、PowerShell、Python 和容器命令不能不加区分地粘贴到同一个终端。

## 5. 每做一步，留下一个能复查的结果

环境采集留版本文件，下载留清单与哈希，构建留命令和日志，服务留实际参数与功能输出，压测留逐请求结果，优化留对照与代价，交付留启停和恢复说明。

使用[适配记录](templates/adaptation-record.md)和[实验记录](templates/experiment-record.md)边操作边记录。最后一章再汇总资料来源，不需要先背完术语。
