| 实例 | 设备 / 模型 | 执行路线 |
| --- | --- | --- |
| 单机双卡 | W7900，Qwen3-30B-A3B / DeepSeek32B/70B | ROCm vLLM、TP2 |

| 双节点 | 每节点8GPU的记录 | Ray组织worker；TP8×PP2表示16rank，不是8卡配置 |

## 完整部署适配流程

1. 每节点记录`rocminfo/rocm-smi`、驱动、ROCm、torch HIP、容器digest与GPU拓扑。两台节点保持同模型文件和版本。
2. 容器先接入`/dev/kfd`和目标`/dev/dri`；在容器内完成小矩阵计算，随后单GPU模型、单机TP，再进入Ray。
3. 分别验证节点间连通、Ray资源注册、RCCL集合通信与模型rank映射。Ray ready只能说明控制面可用，不能代替GPU通信或目标模型执行。
4. 主节点与worker分别执行其角色命令。`ray start --head`只用于head，worker使用`--address`加入；IP、网卡和端口按本地部署配置。
5. 基础模型请求正确后，按目标ctx/seqs加载；保存每rank内存、KV块、通信错误与API输出。

## 加速优化与验收

对比TP/PP时固定总卡数、模型、精度、输入输出与负载。TP增加层内通信，PP引入阶段流水与气泡；不能只因总显存增加就推导速度增加。原文章有重复启动、资源调度与故障迭代，下面完整保留，并以[多设备专题](../chapters/performance/parallelism.md)的角色修订为执行依据。

没有完整吞吐数字的实验不补填数字。新实验至少提供单机/多机的成功请求、实际token、时长、TTFT/TPOT、每rank资源和错误；配置项中的最大并发并非实际并发结果。完整单机、双机操作与排障记录如下。

## R27 · W7900双卡部署Qwen3:30b-A3b

根据您提供的日志信息，模型加载失败的原因可能是由于 GPU 内存不足或配置不当导致的。特别是 RDNA3 架构的 GPU 在处理大型模型时，可能会遇到页面错误（page fault）或内存访问异常。为了解决这个问题，您可以尝试以下几种方法：([CSDN Ask](https://ask.csdn.net/questions/8384253?utm_source=chatgpt.com))

---

##### ✅ 1. 禁用 V1 引擎并强制使用 ROCm Flash Attention

您已经在启动容器时设置了以下环境变量：

```text
-e VLLM_USE_V1=0 \
-e VLLM_USE_TRITON_FLASH_ATTN=0 \
-e VLLM_ATTENTION_BACKEND=ROCM_FLASH \
-e HSA_ENABLE_SDMA=0
```

这些设置有助于禁用 V1 引擎、关闭 Triton Flash Attention，并强制使用 ROCm Flash Attention，从而减少内存占用。

---

##### ✅ 2. 使用张量并行（Tensor Parallelism）

您可以通过设置 `--tensor-parallel-size` 参数来启用张量并行，例如：([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

```text
vllm serve . \
  --served-model-name Qwen3-30B-A3B \
  --host 0.0.0.0 --port 8000 \
  --enable-auto-tool-choice \
  --tool-call-parser hermes \
  --trust-remote-code \
  --tensor-parallel-size 2 \
  --gpu-memory-utilization 0.8
```

这将模型拆分到多个 GPU 上，分散内存负载，从而降低单个 GPU 的内存压力。([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

---

##### ✅ 3. 降低 GPU 内存利用率

通过设置 `--gpu-memory-utilization` 参数，您可以控制每个 GPU 的内存使用比例，例如：

```text
--gpu-memory-utilization 0.8
```

这将限制每个 GPU 使用最多 80% 的显存，避免因内存不足导致的崩溃。

---

##### ✅ 4. 检查 GPU 驱动和硬件兼容性

确保您的 GPU 驱动和硬件与 vLLM 兼容。您可以使用以下 Python 脚本测试 PyTorch NCCL 是否正常工作：([vLLM](https://docs.vllm.com.cn/en/latest/usage/troubleshooting.html?utm_source=chatgpt.com))

```text
import torch
import torch.distributed as dist

dist.init_process_group(backend="nccl")
local_rank = dist.get_rank() % torch.cuda.device_count()
torch.cuda.set_device(local_rank)
data = torch.FloatTensor([1,] * 128).to("cuda")
dist.all_reduce(data, op=dist.ReduceOp.SUM)
torch.cuda.synchronize()
value = data.mean().item()
world_size = dist.get_world_size()
assert value == world_size, f"Expected {world_size}, got {value}"
print("PyTorch NCCL is successful!")
```

如果测试失败，可能需要调整 NCCL 环境变量，例如：([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

```text
export NCCL_P2P_DISABLE=1
```

请注意，这些调整可能影响系统性能，建议仅作为临时解决方案。([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

---

##### ✅ 5. 使用分片模型（Sharded Model）

如果模型过大，无法完全加载到单个 GPU 中，您可以使用分片模型。vLLM 支持将模型分割成多个文件（例如，`model-00001-of-00016.safetensors`），并在启动时加载这些分片。确保您的模型目录结构正确，并在启动命令中指定正确的路径。([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

---

##### ✅ 6. 启用详细日志以进行调试

为了更深入地了解问题，您可以启用详细日志记录：([vLLM](https://docs.vllm.com.cn/en/latest/usage/troubleshooting.html?utm_source=chatgpt.com))

```text
export VLLM_LOGGING_LEVEL=DEBUG
export CUDA_LAUNCH_BLOCKING=1
export NCCL_DEBUG=TRACE
export VLLM_TRACE_FUNCTION=1
```

这将提供更多的调试信息，帮助您定位问题所在。

---

##### ✅ 7. 降级 vLLM 版本

如果您使用的是 vLLM 0.8.2 或更高版本，可能会遇到与注意力机制后端相关的兼容性问题。社区建议将 vLLM 降级至 0.8.1 版本，以解决此类问题。([GitCode Blog](https://blog.gitcode.com/1c3b322891e81373a58c7f7f22d2853d.html?utm_source=chatgpt.com))

您可以使用以下命令安装特定版本：

```text

```

### 二、Head节点操作步骤（<NODE_IP>）

##### 1. 拉取docker镜像（如果已经有可跳过）

```text
bash
Copy code

```

##### 2. 运行Ray head节点容器

这里最关键的，是**启动Ray时显式绑定head节点的内网IP**，确保worker连接时能找到正确地址：

```text
bash
Copy code
```

## R34 · 多节点部署排障

### 多节点部署排障：Ray / NCCL / RCCL / vLLM

> 适用目录：`05-多卡多节点/多节点部署排障.md`

> 关键词：双节点、Ray 能连但模型加载失败、NCCL hang、RCCL 通信失败、vLLM 多节点

---

#### 1. 核心原则

多节点部署要分三层：

```text

控制面：Ray 是否能连接节点

数据面：NCCL/RCCL 是否能完成 GPU 通信

模型面：vLLM 是否能加载权重并完成推理

```

判断顺序：

```text

Ray 能连上

  只能说明控制面通了

NCCL/RCCL all-reduce 成功

  才说明 GPU 数据面通了

vLLM 成功加载模型

  才说明分布式推理链路闭环

```

---

#### 2. 标准排障顺序

不要一上来直接跑大模型。

正确流程：

```text

1. 节点基础网络检查

2. GPU/驱动/CUDA/ROCm 检查

3. 框架版本一致性检查

4. NCCL/RCCL tests

5. PyTorch distributed all-reduce

6. Ray cluster 启动

7. Ray GPU 资源检查

8. vLLM dummy load

9. 小模型真实加载

10. 目标大模型真实加载

11. 压测 TTFT / TPOT / throughput

```

---

#### 3. 基础网络检查

```bash

ping <node_ip>

nc -vz <node_ip> 22

nc -vz <head_node_ip> 6379

nc -vz <head_node_ip> 8265
```

```text

防火墙

head IP 写成 127.0.0.1
```

#### 6. Ray 能连但模型加载失败：重点排查

##### 6.1 模型路径是否两个节点一致

如果启动：

```bash

--model /data/models/deepseek-r1

```

两个节点都必须有：

```bash

ls -lh /data/models/deepseek-r1

du -sh /data/models/deepseek-r1

find /data/models/deepseek-r1 -maxdepth 1 -type f | wc -l

```

Ray 不会自动复制模型权重。

---

##### 6.2 Ray 是否识别 GPU

```bash

ray status

ray list nodes

```

你要看到：

```text

2 nodes alive

GPU: 正确数量

```

如果 GPU 是 0，排查：

```text

驱动不可见

Ray 启动环境没有 GPU 权限

容器没有挂载 GPU 设备

CUDA_VISIBLE_DEVICES / HIP_VISIBLE_DEVICES 设置错误

```

---

##### 6.3 vLLM 是否选错 IP

多网卡机器设置：

```bash

# Node 1

export VLLM_HOST_IP=<NODE_IP>

# Node 2

export VLLM_HOST_IP=<NODE_IP>

```

如果不设置，vLLM 可能选到：

```text

127.0.0.1

docker0

virbr0

错误的管理网卡

```

#### 10. AMD/W7900 双节点经验总结

你之前的场景：

```text

2025 年

双节点服务器

W7900

DeepSeek-R1

Ray 可以连接

RCCL 通信失败或模型无法加载

```

高概率原因：

```text

1. RCCL 选错网络接口

2. 两节点 ROCm/RCCL/PyTorch/vLLM 版本不一致

3. Ray / torch distributed master addr / rank 配错

4. 防火墙、端口、hostname、容器网络问题

5. IB/RDMA 没配好，或者误走 IB

6. W7900 作为工作站卡，多节点 RCCL 验证不如 MI 系列成熟

7. PCIe / NUMA / NIC 拓扑导致通信不稳定

8. DeepSeek-R1 TP/PP 切分不合理

9. 显存不足或模型路径不一致

```

正确复盘话术：

> 当时 Ray 可以把两个 W7900 节点拉成集群，但 vLLM 无法加载模型。这个现象说明 Ray 控制面是通的，但不能证明 GPU 执行面、模型文件访问和 RCCL 通信都正常。我会把问题拆成四类：模型路径和缓存一致性、Ray GPU 资源识别、vLLM/Ray IP 一致性、RCCL collective 初始化。
