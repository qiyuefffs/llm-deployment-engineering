# 写在前面：怎样使用这本书

## 这本书要解决的问题

第一次部署模型时，最容易遇到的困难不是某个参数难记，而是不知道当前问题属于哪一层。下载好权重后，可能发现框架读不了；换成支持的格式后，可能又没有匹配的kernel；模型加载完成后，长请求还可能耗尽内存。进入服务阶段以后，还要区分模型算得慢、请求排队和客户端缓冲。

本书把这些问题放回一条完整链路。先解释设备和模型的约束，再讲引擎怎样执行，随后建立性能与质量检查，最后整理成可维护的服务。一个章节结束时，读者应知道下一步要准备什么，以及怎样确认这一步已经完成。

## 原框架怎样保留

全书保留原稿六部分：知识地图、五层框架、概念库、项目复盘、知识库目录和故障速查。第二部分保留原来的1.1～1.4、2.1～2.6、3.1～3.6、4.1～4.6与5.1～5.3。

每个总章先讲这一层的知识关系。平台细节、完整操作和专题分析放在下级页面。例如，硬件章先解释驱动与Runtime，再进入NVIDIA或AMD；框架章先说明模型加载和请求链路，再进入llama.cpp构建与服务。这样读者无需在同一段教程里来回切换平台。

原稿第五部分的八个主题目录仍然保留为检索入口。它们指向正文中对应的知识与教程，同一套命令有一个主要位置，避免复制多份后发生冲突。

## 阅读前需要了解什么

读者需要会打开终端、进入目录、执行命令和查看文件。Python示例使用基础语法，网络调用优先使用标准库。源码构建章节会使用Git、CMake和编译器，但会解释“配置”与“构建”各自做什么。

不要求先掌握模型训练。与部署直接相关的参数量、注意力、量化、KV和生成阶段，会在对应章节解释。遇到缩写可以查第三部分，再回到当前教程继续操作。

## 三条阅读路线

**从头学习。** 阅读第一部分和第二部分总章，随后按五层顺序学习。在每层做一次最小检查，最后完成工程交付。第三部分作为概念补充，第四至六部分用于日常记录和排错。

**先完成一次运行。** 先做“第一个本地推理服务”。这项练习不使用GPU，模型约610MiB，下载、服务和测试都有完整程序。看到真实响应后，再学习GGUF、tokenizer、上下文、线程、流式和吞吐，概念会更容易对应到文件和日志。

**已有项目需要改进。** 先写任务约束与当前基线，再进入相关章节。内存问题看第4层，模板或API问题看第3层，多节点问题看并行专题。每次修改保留配置与结果，避免一次更换多个组件后无法解释变化。

## 怎样辨认实例与结果

操作实例会说明环境、模型身份、输入、执行顺序和产物。命令中的路径是公开的部署约定，读者使用其他目录时需要一起修改上下游路径。模型别名、磁盘路径与tokenizer路径会明确区分。

作者的历史记录可以说明真实工程中遇到了什么，但部分记录没有完整保存逐请求结果或依赖锁。相关章节会在实例结尾说明缺口。书中新增的CPU演练则公开本轮实际文件；两类材料不会混合成同一次实验。

性能结果要连同负载一起阅读。引擎生成速度、Pipeline内部指标和HTTP吞吐使用不同计时边界，只有条件对应时才比较。功能题通过数也不等于通用模型质量分数。

## 怎样判断自己学会了这一章

读完概念后，尝试用当前工程回答：它发生在哪个阶段？改变了什么资源或执行过程？怎样从日志和结果验证？如果失败，应该回查哪一层？

完成操作后，至少留下环境、有效命令、输入、原始结果与结论。下一位读者拿到这些材料，应能知道你实际做了什么、结果代表什么，以及还没有验证什么。
