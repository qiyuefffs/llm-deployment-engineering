# 工程资料约定与执行基线

[知识体系首页](README.md) · [完整工程实例](cases/README.md)

## 目录规则

保留原框架六部分、五层及1.1～1.4、2.1～2.6、3.1～3.6、4.1～4.6、5.1～5.3节编号。主框架保存定义、组件关系、参数与判断方法；平台专题解释后端细节；`engineering/`保存每个设备从环境到优化的连续记录及FlowUs完整技术文章。

## 每项部署的固定输入

| 输入 | 最低记录内容 |
| --- | --- |
| 任务 | 输入形式、目标输出、最大输入/输出、并发或到达率、TTFT/尾延迟/质量阈值 |
| 设备 | CPU架构、GPU/卡数、RAM/VRAM、互连、驱动、内核、可分配内存 |
| 制品 | model-id/revision、权重/索引、tokenizer、模板、processor、量化配置、摘要 |
| 软件 | 框架commit或版本、torch/Runtime、原生扩展、编译器、构建变量或镜像digest |
| 负载 | 数据文件、seed、采样、输入输出token、缓存冷暖、并发与请求数 |

## 运行目录

```text
deployment/
├── environment/   系统、设备、依赖、镜像、CMake与模块路径
├── artifacts/     模型清单、哈希、转换与量化命令
├── config/        服务、代理、模板与参数
├── inputs/        公开输入、期望输出、负载定义
├── runs/<run-id>/ 请求、响应、日志、metrics、资源、统计
└── operations/    启动、停止、健康、验收与回滚
```

## 结果状态

| 状态 | 证据要求 |
| --- | --- |
| 设备可见 | 系统与框架枚举 |
| 构建通过 | 固定commit、配置和可运行二进制 |
| 模型可执行 | 权重加载、真实输出、结束原因 |
| 功能通过 | 固定任务与期望结果逐项对照 |
| 性能通过 | 目标负载、实际token、成功数、延迟、资源与阈值 |
| 可交付 | 冷启动、异常、停止、恢复、文件与版本可追溯 |

配置命令不自动表示已运行；成功标题不覆盖失败日志；加载完成不表示长上下文和并发已通过。历史工程中的缺失项保留“未记录”，新操作计划保留“待测”。

## 完整源文与技术修订

50份相关FlowUs文章的技术正文写入各设备实例，保留参数、代码块、输出表、失败与后续实验。隐私段落、私人附件与认证信息不公开。路径统一到公开部署约定，节点改为占位符；多节点需要按角色分别填写。

原文存在RTX4080 NVLink、MoE带宽推导、端点字段和并发口径等问题。实例入口给出修订，必要处原位改正；测量数字与错误结论分别处理。[源文清单](evidence/source-coverage.json)列出保留篇目、字符及代码围栏数量。

历史GPU/NPU工程未在本轮重跑。[Windows CPU工程](cases/C14-windows-cpu/README.md)有本机实际文件；公开视觉卡是新测试输入，没有配上未执行的GPU输出。按目录进入对应平台，执行前核对其版本与资源。
