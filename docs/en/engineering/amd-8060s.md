## Key technical revisions and acceptance testing

- MoE doesn't have to read all the experts at every step, and you can't assume that each token will read 65GB with a 65GB file size. Roofline is calculated based on actual data flows and effective bandwidth.
- In the original version, the bandwidth limit for all SSM flash attentions is too wide. This time, the measurements were kept, and the conclusions were limited to fixed models, backend and configuration.
- `--cache-ram 0 ` To control the corresponding version of the host's Prompt cache does not mean shutting down all KVs or necessarily saving GPU bandwidth; `--mlock` It is not possible to activate an accelerator to prevent switching out.
- Prime Q4 is 5.8 times faster than BF16 using round integers and lacks the same quality as full timing. This is not a lossless quantization conclusion.

The following fully preserved deployment articles with BF16 optimization articles; Originally unverified forecasts make sure to remain as forecasts. Formal acceptance testing complements fixed inputs, actual tokens, repeated rounds, resources, peak and quality sets.

##### 4.3 Explanation of the key parameters

|Parameters|Value|Notes|
| --- | --- | --- |
| --n-gpu-layers 99 | 99 |All 41 layers are loaded onto the backend of the GPU Vulkan.|
| --ctx-size 16384 | 16384 |Inference context length ((Reduced KV cache bandwidth pressure))|
| --parallel 1 | 1 |Single slot mode, saving VRAM to the model|
| --threads 16 | 16 |CPU inference number of threads|
| --threads-batch 32 | 32 |Batching number of threads (full use of core)|
| --ubatch-size 1024 | 1024 |Microbatch size (upgraded to GPU parallelism)|
| --batch-size 4096 | 4096 |Suggestions for handling batch sizes|
| --cache-ram 0 | 0 |Disable prompt cache, free up memory bandwidth|
| --poll 50 | 50 |Reduce GPU routing latency|
| --mlock | - |Locking memory pages to prevent swaps|

##### Optimized explanations

- **All 41 layers are offline to the GPU.** Using the unified memory architecture of the AMD Radeon 8060S

- **Flash Attention** Automatically activated

- **Gated Delta Net** Fused + chunked mode enabled on GPU

- **Graph splits**: reduced to 2 (844 on CPU only), substantially reducing kernel launch overhead

- **Prompt Cache** It's off: `--cache-ram 0`), reducing memory bandwidth usage

- **mlock**: locking memory pages to prevent system swaps from affecting inference latency

##### Memory bandwidth limits

- AMD integrates GPUs with unified memory architecture (UMA)

- Real bandwidth: ~100 GB/s

- The BF16 model file is about 65 GB; Each step depends on activation, expert, shared layer, KV and kernel.

- Theoretical analysis revised: the bandwidth model should be the actual memory bandwidth ÷ number of bytes actually read per generated token. MoE is only activation-specific and cannot be routed at the total file size or 16 bytes/token; The original formula does not yield a theoretical result of 6–12 tok/s.

- In fact, it reached: **10 tok/s**(The bandwidth limit has been reached)
