## Full deployment of adaptation processes

1. Each node is recorded `rocminfo/rocm-smi`, drivers, ROCm, torch HIP, container digest, and GPU topology. Both nodes keep the same model files and versions.
2. Container first access `/dev/kfd ` and objectives `/dev/dri`; Small matrix computation is done inside the container, followed by a single GPU model, single-machine TP, and then into Ray.
3. Verify connectivity between nodes, register Ray resources, RCCL collective communication and model rank mapping. Ray ready only indicates that the control panel is available and cannot replace GPU communication or target model execution.
4. The main node and worker execute their role commands respectively.`ray start --head ` Only for head, worker use `--address` to join; IP, network card and port deployment configuration locally.
5. After the basic model request is correct, load according to target ctx/seqs; Save every rank memory, KV block, communication error and API output.

## R27 · W7900 dual-GPU deployment Qwen3:30b-A3b

Depending on the log information you provided, the cause of the model loading failure may have been due to insufficient GPU memory or incorrect configuration. In particular, GPUs with RDNA3 architecture may encounter page errors or memory access errors when processing large models. To solve this problem, you can try the following methods: [CSDN Ask](https://ask.csdn.net/questions/8384253?utm_source=chatgpt.com))

---

##### • 1. Turn off V1 engines and force ROCm Flash Attention

You have already set the following environment variables when you start the container:

```text
-e VLLM_USE_V1=0 \
-e VLLM_USE_TRITON_FLASH_ATTN=0 \
-e VLLM_ATTENTION_BACKEND=ROCM_FLASH \
-e HSA_ENABLE_SDMA=0
```

These settings help turn off the V1 engine, turn off Triton Flash Attention, and force the use of ROCm Flash Attention, reducing memory usage.

---

##### ✅ 2. Using tensor parallelism (Tensor Parallelism)

You can pass the set `--tensor-parallel-size` Parameter to enable tensor parallelism, for example: [vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

```text
vllm serve . \
  --served-model-name Qwen3-30B-A3B \
  --host 0.0.0.0 --port 8000 \
  --enable-auto-tool-choice \
  --tool-call-parser hermes \
  --trust-remote-code \
  --tensor-parallel-size 2 \
  --gpu-memory-utilization 0.8
```

This divides the model into multiple GPUs, distributing the memory workload, thus reducing the memory stress of a single GPU. ([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

---

##### • 3. Reduce GPU memory usage

Passed settings `--gpu-memory-utilization` Parameters can be used to control the memory ratio of each GPU, such as:

```text
--gpu-memory-utilization 0.8
```

This will limit the use of up to 80% of VRAM by each GPU, avoiding crashes caused by insufficient memory.

---

##### • 4. Check GPU drivers and hardware compatibility

Make sure your GPU driver and hardware are compatible with vLLM. You can use the following Python scripts to test whether the PyTorch NCCL is working properly: [vLLM](https://docs.vllm.com.cn/en/latest/usage/troubleshooting.html?utm_source=chatgpt.com))

```text
import torch
import torch.distributed as dist

dist.init_process_group(backend="nccl")
local_rank = dist.get_rank() % torch.cuda.device_count()
torch.cuda.set_device(local_rank)
data = torch.FloatTensor([1,] * 128).to("cuda")
dist.all_reduce(data, op=dist.ReduceOp.SUM)
torch.cuda.synchronize()
value = data.mean().item()
world_size = dist.get_world_size()
assert value == world_size, f"Expected {world_size}, got {value}"
print("PyTorch NCCL is successful!")
```

If the test fails, it may be necessary to adjust the NCCL environmental variables, such as: [vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

```text
export NCCL_P2P_DISABLE=1
```

Please note that these adjustments may affect system performance and are recommended only as a temporary solution. ([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

---

##### • 5. Using the shard model (Sharded Model)

If the model is too large to fully load into a single GPU, you can use the shard model. vLLM supports splitting models into multiple files (e.g., `model-00001-of-00016.safetensors`), and load these shards at startup. Make sure that your model directory is structured correctly and that you specify the correct path in the boot command. ([vLLM](https://vllm.hyper.ai/docs/getting-started/troubleshooting/?utm_source=chatgpt.com))

---

##### • 6. Enable detailed logs to moderate

For a more in-depth understanding of the problem, you can enable detailed log records: [vLLM](https://docs.vllm.com.cn/en/latest/usage/troubleshooting.html?utm_source=chatgpt.com))

```text
export VLLM_LOGGING_LEVEL=DEBUG
export CUDA_LAUNCH_BLOCKING=1
export NCCL_DEBUG=TRACE
export VLLM_TRACE_FUNCTION=1
```

This will provide more debugging information to help you locate the problem.

---

##### 7.Downgrade the vLLM version

If you are using vLLM 0.8.2 or higher, you may encounter compatibility issues related to the backend of the attention mechanism. The community recommends that vLLM be upgraded to version 0.8.1 to address these issues. ([GitCode Blog](https://blog.gitcode.com/1c3b322891e81373a58c7f7f22d2853d.html?utm_source=chatgpt.com))

You can install specific versions using the following commands:

```text
pip install vllm==0.8.1
```

If you try the above method, you should be able to solve the problem of model loading failure. If the problem persists, please provide more error logs and system information for further diagnosis.

## R34 · Multi-node deployment barrier

### Multi-node deployment barrier: Ray / NCCL / RCCL / vLLM

> The following lists are available: `05-多卡多节点/多节点部署排障.md`

> Keywords: dual nodes, Ray connects but model loads fail, NCCL hang, RCCL communication failure, vLLM multi-node

---

#### 1. Core principles

Multi-node deployments are divided into three layers:

```text

控制面：Ray 是否能连接节点

数据面：NCCL/RCCL 是否能完成 GPU 通信

模型面：vLLM 是否能加载权重并完成推理

```

In order to judge:

```text

Ray 能连上

  只能说明控制面通了

NCCL/RCCL all-reduce 成功

  才说明 GPU 数据面通了

vLLM 成功加载模型

  才说明分布式推理链路闭环

```

---

#### 2. Standardized barrier order

Don't just run a large language model.

The right process:

```text

1. 节点基础网络检查

2. GPU/驱动/CUDA/ROCm 检查

3. 框架版本一致性检查

4. NCCL/RCCL tests

5. PyTorch distributed all-reduce

6. Ray cluster 启动

7. Ray GPU 资源检查

8. vLLM dummy load

9. 小模型真实加载

10. 目标大模型真实加载

11. 压测 TTFT / TPOT / throughput

```

#### 8. TP/PP configuration

The two nodes suggest:

```text

PP = 节点数

```

##### 2 knots, 8 cards per knot

```bash

```

##### 2 knots, 4 cards each.

```bash

--tensor-parallel-size 4 \

--pipeline-parallel-size 2
```

#### 10. AMD/W7900 Dual-Node Experience Summary

You've seen the scene before:

```text

2025 年

双节点服务器

W7900

DeepSeek-R1

Ray 可以连接

RCCL 通信失败或模型无法加载

```

The reasons for the high probability:

```text

1. RCCL 选错网络接口

2. 两节点 ROCm/RCCL/PyTorch/vLLM 版本不一致

3. Ray / torch distributed master addr / rank 配错

4. 防火墙、端口、hostname、容器网络问题

5. IB/RDMA 没配好，或者误走 IB

6. W7900 作为工作站卡，多节点 RCCL 验证不如 MI 系列成熟

7. PCIe / NUMA / NIC 拓扑导致通信不稳定

8. DeepSeek-R1 TP/PP 切分不合理

9. 显存不足或模型路径不一致

```

It's the right retrospective saying:

> At the time, Ray could pull two W7900 nodes into clusters, but vLLM could not load the model. The phenomenon indicates that the Ray controls are normal, but cannot prove that the GPU execution, model file access and RCCL communication are normal. I separate the issues into four groups: model-path/cache consistency, Ray GPU resource discovery, vLLM/Ray IP consistency, and RCCL collective initialization.

#### 11. Common error speed charts

|The phenomenon|Priority screening|

|---|---|

|Ray can connect, model load failure|The model path, the GPU resources, the VLLM_HOST_IP, the NCCL/RCCL|

|Ray only shows one node.|Workers without connections, ports, firewalls, head IP|

|Ray shows GPU = 0.|GPU permissions, CUDA_VISIBLE_DEVICES, and container device access|

|VLLM card in loading model|Model files, VRAM, safetensors, and worker died|

| NCCL hang |NICs, IB/RDMA, NCCL_SOCKET_IFNAME, and ports|

| RCCL hang |Internet cards, ROCm/RCCL versions, IB, W7900 support for borders|

|One node can run, two nodes fail|network, NCCL/RCCL, TP, cross-node, and Ray IP|

|Dummy Success is Failure|weights / VRAM /IO|

|dummy failure|scheduling / communication /IP/ parallelism configuration|
