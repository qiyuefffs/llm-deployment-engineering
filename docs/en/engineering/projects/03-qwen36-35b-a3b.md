# Qwen3.6-35B-A3B Deployment and Performance

[Project index](README.md) · [General methodology](../edge-llm-performance-methodology.md)

## 1. Applicable scenario

- Qwen3.6-35B-A3B Q4_K_XL, about 35B total and 3B activated.
- Fits on one device; focus is decode, concurrency, context budget, and backend choice.
- Text-only GGUF chain; text success is not multimodal acceptance.

## 2. Recommended route

| Target | Route |
| --- | --- |
| Multi-request concurrency | HIP/ROCm no-spec replicas |
| Single-stream decode study | Vulkan or MTP comparison |
| Fixed-total long context | HIP single, MTP off |
| Capacity scaling | Two replicas with load balancing |
| Not recommended as default | Dual RPC when one device already fits |

## 3. Minimum procedure

1. Build HIP and Vulkan separately and inspect devices.
2. Pass health, models, streaming, and full output.
3. Calculate per-slot context from `-c / -np`.
4. Deploy single, RPC, and replicas separately.
5. Test MTP off/on in separate groups.
6. Record per-stream decode, slowest stream, TTFT, and P95.

## 4. Test matrix

- Fixed total context: 32K/64K/128K, concurrency 1/3/5.
- HIP/Vulkan × single/dual × MTP off/on.
- 128 output, prompt cache off, F16 KV, FA on.
- Replica capacity: 1K/4K/8K/16K input, 512 output.

## 5. Representative results

- 72 fixed-context scenarios completed with full integrity.
- HIP single with MTP off had the lowest wall time in every fixed-context case.
- MTP raised wall time by about 4.8%-9.0% across aggregate groups.
- Dual RPC was about 7%-15% slower than the matching single backend.
- Temporary replica capacity: short 24, normal 27, RAG 18, long 9 offered.
- HIP beat Vulkan for 4K/8K/16K replica workloads.

## 6. Boundary

- Fixed-total and fixed-per-request workloads are different.
- 128 and 512 output matrices are not directly rankable by TPS.
- Offered concurrency above active slots includes queueing.
- MTP is mostly negative at concurrency boundaries and is off by default.
